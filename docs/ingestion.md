# Ingestion

## Copyright

**This repository never includes commercial copyrighted music, and never
downloads any.** `testdata/` contains only synthetic tone-sequence fixtures
generated by code (see `processor/tests/conftest.py` and
`scripts/dev/generate_test_catalog.py`) — nothing recognizable as a real
song. The ingestion pipeline is a tool you point at audio **you** already
have the rights to (music you own, licensed catalog files, public-domain
recordings) — it does not scrape, search for, or download anything.

## The CLI

```bash
cd processor && source .venv/bin/activate

python -m music_fingerprint ingest ./path/to/music
# or, after `pip install -e .`:
music-fingerprint ingest ./path/to/music
```

Requires `DATABASE_URL` (env var or `--database-url` flag) pointing at a
migrated Postgres instance.

### What it does, per file

1. **Discover**: recursively walk the directory for `.wav .flac .mp3 .m4a
   .aac .ogg`.
2. **Identity check**: SHA-256 the file's bytes. If that hash is already in
   `ingested_sources`, skip it — **ingestion is idempotent**, re-running
   over the same directory (or a directory with overlapping files) never
   creates duplicate catalog entries. Identity is content-based, not
   filename/mtime-based, because those are unreliable (a renamed or
   re-exported file with identical audio is still the same recording, and
   the ingestion tool should recognize that).
3. **Decode + validate**: same canonical decode path as the query path
   (mono, resampled to 11025Hz, peak-normalized) via `soundfile`, with an
   `ffmpeg` fallback whenever `soundfile` can't parse it — regardless of
   the file's extension, since extensions are routinely wrong in the wild
   (e.g. AAC/M4A content saved with a `.mp3` extension by some download
   tools; `ffmpeg` probes actual content, not the name, to pick a
   demuxer). Corrupted files, zero-length audio, and genuinely
   unsupported codecs raise `AudioValidationError` and are recorded as
   `failed` — **one bad file never aborts the whole run**.
4. **Metadata**: best-effort ID3/FLAC/MP4 tag read via `mutagen`
   (`title`/`artist`/`album`/`albumartist`); if tags are missing, falls
   back to parsing `"Artist - Title.ext"` from the filename, else uses the
   filename stem as the title and `"Unknown Artist"`. Tags are never
   trusted for anything beyond display metadata (parameterized queries
   only — see `ingestion.py`).
5. **Fingerprint**: the same `generate_fingerprints` reference
   implementation used everywhere else (see
   [fingerprinting.md](fingerprinting.md)).
6. **Insert**: one real Postgres transaction per file — the `songs` row,
   every fingerprint row, and the `ingested_sources` ledger entry commit
   together. If the process crashes mid-run, already-committed files stay
   committed and are skipped (not redone) on the next run; the file being
   processed at crash time is simply retried from scratch next run (its
   SHA-256 was never recorded, so it isn't considered "already ingested").
7. **Report**: a running progress log (every 10 files by default) and a
   final summary of ingested / skipped / failed counts, with failure
   reasons.

### Bulk insert: `COPY`, not `INSERT`

Fingerprint rows are loaded via Postgres `COPY ... FROM STDIN`
(`psycopg`'s `cursor.copy()`), not one `INSERT` per row and not even a
batched multi-row `INSERT`. For a single song this can be thousands of
rows; for a real catalog it's the difference between an ingestion run that
takes minutes and one that takes hours. See [database.md](database.md) for
the scaling rationale.

(The `POST /api/v1/admin/ingest` HTTP endpoint, in contrast, uses a
`UNNEST`-based batched `INSERT` and is capped at 200k fingerprints per
request — see [api.md](api.md). That endpoint exists for small/API-driven
additions, not catalog-scale ingestion; round-tripping millions of
fingerprint rows through JSON-over-HTTP would be needlessly slow.)

## Format support

| Format | How |
|---|---|
| WAV, FLAC, MP3, OGG | `soundfile` (libsndfile) — direct, no shell-out |
| AAC, M4A, and anything else `soundfile` rejects | `ffmpeg` subprocess fallback (content-probed, not extension-gated), invoked with an explicit argv list — never a shell string, no command-injection surface even though the input is untrusted |

Anything `ffmpeg` also can't make sense of fails with a clear
`AudioDecodeError` rather than silently skipping or crashing.

## Safety

Untrusted input handling applies identically to ingestion and to query
audio (see [fingerprinting.md](fingerprinting.md) §1): payload size caps
(`DEFAULT_MAX_INGEST_BYTES`, 500MB — generous enough for uncompressed WAV
of a long track), duration caps (`max_ingest_duration_seconds`, default
3600s), and peak-density capping in the fingerprinter itself protect
against decompression-bomb-style or adversarially dense audio regardless
of where it enters the system.

## Example

```bash
# One-time: apply migrations (or just start the backend once, which does
# this automatically — see backend/src/storage/db.rs)
make migrate

# Ingest a directory you own the rights to
DATABASE_URL=postgresql://postgres:devpass@localhost:5432/loony_shazam \
  music-fingerprint ingest ~/Music/MyLicensedCatalog

# Verify
psql $DATABASE_URL -c "SELECT count(*) FROM songs;"
psql $DATABASE_URL -c "SELECT count(*) FROM fingerprints;"
```

For local development/testing without any real audio files, generate a
small synthetic catalog instead:
```bash
python3 scripts/dev/generate_test_catalog.py /tmp/test_catalog --num-songs 5 --duration 25
music-fingerprint ingest /tmp/test_catalog
```
